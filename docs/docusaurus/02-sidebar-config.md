# 2. 侧边栏配置 · 本站为什么只要 67 行

*官方文档把 `sidebars.js` 的写法列了七八种（手写文档 id、分类、链接、分隔线……）。本站一个都没用——因为栏目一旦多起来，手写 id 就是持续出错的源头。*

---

## 一、整体形状：一个函数 + 两张清单

```javascript
function column(dirName) {
  const {label = dirName, collapsible = true, collapsed} = readCategoryMeta(dirName);
  return {
    type: 'category',
    label,
    collapsible,
    ...(collapsed === undefined ? {} : {collapsed}),
    items: [{type: 'autogenerated', dirName}],
  };
}

const CODE_COLUMNS = ['react', 'rust', 'python', 'docusaurus'];
const KNOWLEDGE_COLUMNS = ['patterns', 'math', 'physics', 'education', 'poetry'];
```

`sidebars.js` 只负责三件事：**哪些栏目存在、以什么顺序出现、「编程」要不要聚合成一层**。栏目的显示名和折叠状态一律不写在这里。

---

## 二、必须包一层 category：autogenerated 的坑

Docusaurus 的 `autogenerated` 会展开 `dirName` 目录里的**内容**，但**不会把该目录本身变成一个分类**。

所以 `{type: 'autogenerated', dirName: 'math'}` 单写出来的效果是：12 篇数学文档全部平铺在顶层，和物理、诗歌混在一起，导航层级整个塌掉。`column()` 存在的唯一理由，就是手工补上那层缺失的分类壳。

:::warning 别把 column() 换成裸 autogenerated
这是本站侧边栏最脆弱的一行。看到"简化"成 `items: [{type: 'autogenerated', dirName}]` 的提议，先跑 `npm run start` 看左栏还剩几层。
:::

---

## 三、显示元数据下沉到 `_category_.json`

每个栏目目录里放一份就近的元数据，例如 `docs/physics/_category_.json`：

```json
{
  "label": "物理",
  "collapsible": true,
  "collapsed": false
}
```

`column()` 读它，读不到就用目录名兜底（`readCategoryMeta` 里包了 `try/catch`）。于是：

- 改栏目显示名 → 改目录里那份 json，不用碰根目录的 `sidebars.js`
- 子目录（如 `docs/docusaurus/主配置/`）没有 json → Docusaurus 直接用目录名当标签，也是对的
- 顺序仍由 `sidebars.js` 的两张清单决定；json 里的 `position` 字段本站不读取

同一目录内的文档顺序由**文件名数字前缀**决定（`01-`、`02-`……），前缀同时被 `scripts/gen-tracks.js` 当作站点序号，见下一节契约。

---

## 四、契约：文件名序号 = frontmatter slug

左侧导航只管"显示"，学习进度是另一套系统：客户端按 URL 里的 slug 记「已读」，学习地图按文件名序号点亮站点。两者必须相等，否则读过的站点会点不亮，或者点亮隔壁那篇。

这条契约由构建期脚本兜住——`npm run gen-tracks`（以及任何一次 `npm run build`）会检查并报错：

```text
docs/math/05-gauss-sum-induction.md: slug “6” 与文件名序号 5 不一致
（进度按 slug 记录，站点按序号点亮，两者必须相等）
```

同类契约还有：`mapShort` 必填（地图上的站名）、`concepts` 只能用 `src/data/concepts.cjs` 里的 id、且每个概念至少落在 2 条线路上。**写错就构建失败**，不留到线上发现。

---

## 五、新增一个栏目：五处改动，顺序不能换

| 步骤 | 改哪里 | 作用 |
|---|---|---|
| 1 | 建 `docs/<id>/` 目录 + `_category_.json` | 侧边栏显示名与折叠状态 |
| 2 | 放 `01-xxx.md`（frontmatter 含 `slug: '1'`、`mapShort`） | 第一篇正文 |
| 3 | `sidebars.js`：把 id 加进 `CODE_COLUMNS` 或 `KNOWLEDGE_COLUMNS` | 左栏出现该栏目 |
| 4 | `src/data/columns.cjs`：加一行 | 导航下拉、页脚、首页卡片入口 |
| 5 | `scripts/gen-tracks.js` 的 `STYLE`：加 `{color, kind}` | 学习地图画这条线 |

第 5 步漏掉的后果最隐蔽：栏目在导航里能用，但地图上找不到线，首页卡片也不显示。历史上 Java 线就是这样变成"读了记不进进度"的断头线，最后整条撤下——现在编程栏只有 React / Rust / Python 三条线在地图上跑。

---

## 六、删栏目相反：先从 `columns.cjs` 摘

顺序是 5 → 4 → 3 → 目录。只删目录不清单据，`gen-tracks` 会报"栏目不存在"；只清单据不删 `STYLE`，则留下一条永远为空的线。

:::info 一句话带走
**`sidebars.js` 是薄层，元数据贴着内容放，一致性交给构建期脚本。** 9 个栏目能靠 67 行撑住，靠的不是 Docusaurus 的自动能力，而是"把易错项变成会失败的检查"。
:::
