# 阶段 4：⭐ 所有权（Ownership）

> 这一章是 Rust 的**灵魂**。看懂它，后面 90% 的编译错误你都能自己解释；看不懂，你会一辈子都在和编译器搏斗。

## 🎯 学习目标

- 明白 Rust **不用 GC、也不用手动 free**，靠的是什么
- 掌握所有权的**三条规则**
- 理解 **move 语义**——为什么 `let b = a;` 之后 `a` 就不能用了
- 分清 **Copy trait、Clone trait、Move** 三种"赋值"行为
- 遇到 `E0382: use of moved value` 不再慌张

---

## 🍔 一句话比喻

> **Rust 的变量像"一次性快递包裹"**：
> - 每个包裹（值）**只有一个收件人**（owner）
> - 你把包裹交给别人（**move**）之后，你手上就**空了**——不是复制一份，是**整个转手**
> - 收件人一旦被换掉（离开作用域），包裹当场拆掉释放（**drop**）
> - 想让别人也有？要么**明说复制**（`.clone()`），要么**类型本身可复制**（`i32` 这种小东西）
>
> 对比其他语言：
> - **C**：你可以随意 memcpy 指针，也可能 double-free 崩掉
> - **Python/JS**：多个变量指向同一个对象，GC 帮你算引用次数
> - **Rust**：**在编译期就把上面两条路堵死**——你只能有一个 owner，编译器盯着

---

## 一、为什么需要所有权？

看这段 C 代码的噩梦：

```c
char *make() {
    char *s = malloc(10);
    return s;         // 谁负责 free？调用者？
}
int main() {
    char *a = make();
    char *b = a;      // a 和 b 指向同一块内存
    free(a);
    // 忘记 b 还在用，或者 free(b) → double free → UB
}
```

Python/JS 没这个问题，因为有 **GC**——代价是运行时开销、内存抖动、stop-the-world。

Rust 走第三条路：**编译期追踪每个值的归属**，作用域结束时自动 `drop`，无 GC 无 UB 无 double-free。

---

## 二、三条规则（背下来）

1. **每个值都有一个 owner（变量）**
2. **同一时刻只能有一个 owner**
3. **owner 离开作用域时，值被 drop（释放）**

就这三条，编译器严格执行。

---

## 三、Move：赋值的默认行为

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;             // ⚠️ s1 被 move 到 s2
    println!("{}", s1);      // ❌ E0382: borrow of moved value: `s1`
    println!("{}", s2);      // ✅ "hello"
}
```

### 内存层面发生了什么？

`String` 由三部分组成：`ptr`（指向堆）+ `len` + `capacity`。

**赋值前**：
```
栈: s1 = [ptr → 堆"hello", len=5, cap=5]
堆: "hello"
```

**赋值后**（浅拷贝结构体，但堆所有权移交）：
```
栈: s1 = [已失效]        ← Rust 主动把 s1 标记为未初始化
栈: s2 = [ptr → 堆"hello", len=5, cap=5]
堆: "hello"
```

如果允许 `s1` 和 `s2` 都存活，函数结束时两次 `drop` → **double free**。Rust 直接在编译期禁止这种可能：`s1` 被"作废"，你再也用不了。

### 图：move vs 浅拷贝

```mermaid

```

```mermaid
    end
```

## 四、Clone：显式深拷贝

想要 s1 和 s2 都保留？自己写 `.clone()`：

```rust
let s1 = String::from("hello");
let s2 = s1.clone();          // ✅ 堆上也复制一份
println!("{} {}", s1, s2);    // 都能用
```

:::warning clone 是有成本的
`String::clone` 会分配新内存并 memcpy 内容。写 `clone` 之前问自己：是真的需要两份，还是我其实应该用**借用**（下一章 `&s1`）？
:::

## 五、Copy trait：小东西自动按位复制

```rust
let x = 5;
let y = x;             // ✅ x 还能用！
println!("{} {}", x, y);
```

为什么 `i32` 可以，`String` 不行？

因为 `i32` 完全在栈上，就是一个数——**"复制"和"移动"没区别**，编译器直接按位复制，标记为 `Copy`。

### 实现了 Copy 的类型（默认）

- 所有整数（`i32`/`u8`/`usize`...）、浮点、`bool`、`char`
- **全部字段都 Copy** 的元组，如 `(i32, bool)`
- 固定大小数组 `[i32; 5]`（元素 Copy 才 Copy）

### **不**是 Copy 的类型

- `String`、`Vec<T>`、`HashMap<K,V>` — 有堆内存
- 实现了 `Drop` 的类型（自己管理释放逻辑）
- 元组里含非 Copy 元素，如 `(String, i32)`

:::info 一条铁律
**凡是堆上存东西的类型，都不是 Copy**，赋值 = move。这是理解 Rust 的钥匙。
:::

## 六、函数与所有权

```rust
fn takes(s: String) {
    println!("{}", s);
}   // s 在这里 drop

fn gives() -> String {
    String::from("created")
}   // 返回值所有权移交调用者

fn main() {
    let s = String::from("hi");
    takes(s);              // s move 进函数
    // println!("{}", s);  // ❌ s 已失效

    let s2 = gives();      // 返回值的 owner 是 s2
    println!("{}", s2);
}
```

**规则**：把值传进函数 = move 到函数；函数返回 = move 回调用者。

想让函数"看一眼"但不拿走？用**引用**（下一章）。

---

## 七、什么时候值会被 Drop？

owner 离开作用域时。Rust 保证 drop 顺序：**局部变量按声明顺序反向 drop**。

```rust
{
    let a = String::from("a");
    let b = String::from("b");
    // 结束时先 drop b，再 drop a
}
```

自定义清理逻辑用 `Drop` trait：

```rust
struct File { handle: u32 }
impl Drop for File {
    fn drop(&mut self) {
        println!("关闭 fd {}", self.handle);
    }
}
```

:::tip RAII 思维
C++ 的 RAII 在 Rust 里是**默认**。作用域 = 资源边界。这也是为什么 Rust 几乎没有 `close()` / `unlock()` 手动操作。
:::

## 八、E0382 常见触发场景（对照表）

| 代码 | 报错原因 | 修法 |
|---|---|---|
| `let b = a; println!("{}", a);` | a 被 move | `a.clone()` 或 `&a` |
| `for s in vec![a, b] { use(s) }` 之后再 `use(a)` | 集合元素 move 走 | 迭代 `iter()` 拿引用 |
| `fn f(s: String) { ... }` 传 `a` 后又用 `a` | 参数 move | 参数改成 `&String` 或 `&str` |
| `let mut a = ...; g(&mut a); println!("{}", a);` | 可变借用未结束又用 | 缩小 `&mut a` 作用域 |

## 九、实战：改一段"编译不过"的 Rust 代码

原始（有 bug）：

```rust
fn calculate_length(s: String) -> usize {
    s.len()
}   // s 在这里 drop

fn main() {
    let s = String::from("hello");
    let len = calculate_length(s);
    println!("Length of {} is {}", s, len);   // ❌ s 已 move
}
```

**修法 A**：clone（浪费内存）

```rust
let len = calculate_length(s.clone());
```

**修法 B**（推荐）：借用引用

```rust
fn calculate_length(s: &String) -> usize { s.len() }
let len = calculate_length(&s);   // ✅ s 仍归 main
```

引用（`&String`）是 Rust 学习方向中的下一个主题：它把"看一眼但不拥有"的语义包装成类型，属于后续要展开的 **借用与生命周期** 部分。

---

## ✅ 阶段 4 总结

1. **Rust 用所有权替代 GC 和手动 free**——编译期决定释放时机
2. **三条规则**：一值一 owner；赋值 = move；owner 出作用域 = drop
3. **Copy 类型（栈上小数据）自动复制；堆类型（String/Vec）默认 move**
4. **想同时保留 → `.clone()`；想"看一眼"就还回来 → 引用 `&T`（后续学习方向）**
5. `E0382` 是 Rust 学习曲线里最常见的错误，看到它先想：**谁 move 了？我能不能改成借用？**

<details>
<summary>练习 2：改写函数，避免 clone</summary>

**原始**：

```rust
fn print_first_word(s: String) -> String {
    let word = s.split(' ').next().unwrap().to_string();
    println!("{}", word);
    s   // 返回原字符串
}
```
调用方 `let s2 = print_first_word(s.clone());` — 每次都要 clone，很浪费。

**改进（用引用）**：

```rust
fn print_first_word(s: &String) -> &str {
    s.split(' ').next().unwrap()
}

let s = String::from("hello world");
print_first_word(&s);
println!("{}", s);   // s 完好
```

（`&String` 还可以进一步简化为 `&str`，下一章细说）
</details>
